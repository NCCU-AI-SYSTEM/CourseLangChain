## 本週實作內容

### 1. 新增 `agents/` 模組

```
CourseLangChain/
└── agents/
    ├── __init__.py
    └── brain_agent.py    ← 本週交付物
```

`brain_agent.py` 用 `langgraph.prebuilt.create_react_agent` 包兩個既有 `@tool`：

- `text_to_sql_tool`（時間限制 → SQL WHERE 子句）
- `retrieval_tool`（BM25 / FAISS 課程檢索，可吃 sql_filter）

工具呼叫順序由 LLM 透過 ReAct loop 自行決定，不再寫死條件分支。

### 2. 為什麼從 `OllamaLLM` 換成 `ChatOllama`

原本 `agent/nodes.py` 用的是 `OllamaLLM`（text completion 介面），**不支援 tool calling**。
Brain Agent 必須走 chat / function-calling 介面，因此 `brain_agent.py` 內統一使用：

- `ChatOllama`（本機推論）
- `ChatGoogleGenerativeAI`（Gemini 路徑）

注意：`llama3.2:1b` 在 tool calling 上不夠穩，建議實測時換成 `llama3.1:8b` 或 `qwen2.5`，
否則 Ollama 路徑下 agent 可能無法正確產生 tool call。Gemini 路徑沒有此問題。

### 3. 與舊 graph 共存（向後相容）

新增 `USE_BRAIN_AGENT` 環境變數：

- `false`（預設）→ 走原本的 `agent.graph.streaming_graph`，行為完全不變
- `true` → `CourseLangGraph.invoke / astream` 改走 `brain_agent`

`main.py` 內 `CourseLangGraph` 類別保留同樣的 `invoke()` / `astream()` 介面，
所以 `app.py`、`streamlit.py`、CLI 全部不用改，前端 SSE 串流路徑也不用動。

### 4. 串流路徑

Brain Agent 的串流走 `astream_events(version="v2")`，過濾 `on_chat_model_stream` 事件，
yield `chunk.content`，與舊 graph 的串流輸出格式一致，前端 `Chat.vue` 不需要任何改動。

## 已知取捨與待辦

### 取捨

- **暫時放棄 `validate_sql` 的 3 次重試硬門檻**：`create_react_agent` 內建的 ReAct loop
  會在工具失敗時自然重試，但沒有「最多 3 次」的硬上限。若實測發現 LLM 容易在 SQL 失敗時
  陷入長迴圈，再考慮把 `validate_sql` 包成第三個 tool，或在 `text_to_sql_tool` 內部
  自己 try-execute 一次後回 fallback。

- **不再有 `should_skip_sql` 條件函式**：靠 prompt + LLM 判斷取代。優點是維護成本低、
  擴充新工具時不必改路由；缺點是行為依 LLM 強度浮動（`llama3.2:1b` 不夠用）。
